# 8A — INVALIDATION MODEL

## 1. INPUT
Validated setup/confirmation evidence, structural references, risk parameters.

## 2. PROCESSING
Translate validated trade premise into a risk invalidation reference; distinct from 6D setup invalidation.

## 3. OUTPUT
Risk invalidation level/model, assumptions, confidence, reasons.

## 4. GATE
BLOCK when a defensible invalidation cannot be defined.

## 5. SCORE
Model quality 0–100; hard risk gates prevail.

## 6. TRACEABILITY
Record setup ID, structural references, risk config/version, calculation, timestamp.

**DECISION BOUNDARY:** risk model only.
