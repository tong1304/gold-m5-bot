# GOLD G9-G11 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add GOLD-only G9 Liquidity Sweep + CHoCH, G10 Continuation FVG Pullback, and G11 Session Breakout + Retest to V12.2 while preserving BTC E1-E8 behavior, strict MTF data-quality gates, replay no-lookahead, and the existing risk pipeline.

**Architecture:** Keep `v11/engine.py` as the orchestration boundary. Put G9-G11 detection in a dedicated GOLD strategy module with the same candidate contract as existing strategies, then extend strategy dispatch, GOLD priority, risk evidence, setup-state/pending-limit replay, catalog metadata, and statistics serialization. BTC remains on the existing E1-E8 path.

**Tech Stack:** Python, pandas, pytest, existing V12.2 strategy/risk/replay modules, GitHub Actions/Render deployment.

**Spec:** `docs/superpowers/specs/2026-08-25-gold-g9-g11-design.md`

## Global Constraints

- GOLD only for G9-G11; BTC remains E1-E8 only.
- No live order execution; analysis/signal-only remains enforced.
- H1/M15/M5 data-quality validation remains a hard gate; never fabricate missing candles.
- Replay and live evaluation use only candles closed/available at the M5 trigger.
- G9 is `PENDING_LIMIT`; G10/G11 are `MARKET`.
- G9 minimum RR is 1.5R; G10 minimum RR is 2.0R; G11 minimum RR is 1.0R.
- GOLD 150-point FVG threshold uses actual instrument point size/precision.
- Existing `v11/risk.py` remains the single risk calculation path.
- New GOLD priority is G9 > G10 > G11 > E7 > E4 > E1 > E2 > E5 > E3 > E6 > E8.
