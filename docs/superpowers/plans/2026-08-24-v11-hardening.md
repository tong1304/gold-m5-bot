# V11 Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make V11 the single deterministic decision path for live, replay, and validation while removing legacy-state, stale-setup, persistence, and concurrency risks.

**Architecture:** V11 receives validated closed-candle LSE data and performs M15 context, M5 strategy evaluation, freshness/quality ranking, M15 alignment, and a single risk gate. Live scanning, replay, and validation call the same V11 engine contract; legacy engines remain available only for explicitly named legacy endpoints/workflows.

**Tech Stack:** Python 3.12, pandas, Flask, SQLite-compatible persistence, GitHub Actions, pytest.

**Spec:** Approved in chat on 2026-08-24: V11 Hardening — unified Live/Replay/Validation, LSE data, deterministic strategy selection, freshness, centralized risk, persistent duplicate protection, and no live orders.

## Global Constraints

- V11 is signal-only; `live_orders_allowed=False` remains mandatory.
- V11 uses closed M5 candles and only M15 candles closed by the M5 close timestamp.
- V11 minimum RR is exactly 2.0 unless a future explicit design changes it.
- Live, replay, and validation must use the same V11 decision contract.
- LSE is the V11 historical/live market-data source.
- Legacy V5/V9/V10 code must not be imported by the V11 validation/replay path.
- No strategy is selected solely because it appears first in a registry.
- Setup freshness must be explicit and bounded.
- Persistent history must survive process restart; duplicate suppression must be atomic.
